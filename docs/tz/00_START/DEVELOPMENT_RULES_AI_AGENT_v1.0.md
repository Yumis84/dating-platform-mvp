# DEVELOPMENT RULES AI AGENT

Правила разработки проекта Dating Platform MVP v1.0

Единые правила для всех AI-агентов | Версия: 1.0 | Дата: 06.08.2026

## 1. Работа с документацией

- Все AI-агенты перед началом работы обязаны изучить README.
- Далее изучать документы строго по порядку (00 → 13).
- Запрещено начинать разработку без анализа архитектуры.

## 2. Управление файлами

Главный файл контроля проекта: PROJECT_STATUS_MVP_v1.0

Правила:
- существует только один актуальный файл;
- запрещено создавать дубликаты;
- перед созданием нового файла проверять наличие существующего;
- старые версии перемещать только в 99_ARCHIVE.

## 3. Версионность

Формат: MVP v1.0
Изменения: v1.1 → v1.2 → v2.0
Все изменения должны фиксироваться в PROJECT_STATUS и в названии/содержимом документа.

## 4. Работа с ТЗ

- выполнять только согласованные задания;
- не пропускать этапы;
- не переходить к следующему ТЗ без подтверждения;
- изменения бизнес-логики согласовывать.

## 5. Работа с n8n

- каждый workflow имеет уникальное имя;
- перед созданием проверять существующие workflow;
- сохранять резервные копии JSON;
- не удалять рабочие версии без подтверждения;
- добавлять описание назначения workflow.

## 6. Работа с базой данных

Перед изменением структуры:
- описать новые таблицы;
- описать поля;
- описать связи;
- получить согласование.

## 7. Работа с AI

AI должен:
- анализировать перед созданием;
- объяснять архитектурные решения;
- сообщать о рисках;
- не придумывать отсутствующие данные.

## 8. Формат отчётов

После каждого этапа предоставлять:
- что сделано;
- какие файлы созданы;
- какие изменения внесены;
- какие проблемы найдены;
- следующий шаг.

## 9. Безопасность

Запрещено:
- публиковать API ключи;
- хранить пароли в документах;
- удалять логи без причины;
- менять доступы без согласования.

## 10. Главный принцип проекта

Сначала: **анализ → архитектура → согласование → реализация → тестирование**
