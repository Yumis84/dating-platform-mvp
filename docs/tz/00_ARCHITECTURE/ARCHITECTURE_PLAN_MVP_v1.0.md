# АРХИТЕКТУРНЫЙ ПЛАН РЕАЛИЗАЦИИ

Dating Platform MVP v1.0

Результат задания AI Agent №00 | Версия: 1.0 | Дата: 06.08.2026

## 1. Общая архитектура системы

Платформа построена по модели Telegram-first: пользователь взаимодействует только через Telegram, а вся бизнес-логика централизована в n8n.

### 1.1. Компоненты

- Telegram Bot — точка входа, команды, уведомления, доставка сообщений девушкам.
- Telegram WebApp — визуальный интерфейс: каталог, карточки анкет, чат, встречи, личный кабинет, статусы.
- n8n — единственный backend-движок: webhook, триггеры, бизнес-логика, запись в БД, уведомления, cron.
- AI Agent — создание анкет (диалог), модерация текста/отзывов, антиспам, помощник администратора.
- Хранение данных (MVP) — Google Sheets; далее PostgreSQL.
- Админ-часть — Telegram-бот для администратора + уведомления; позже — WebApp-раздел.

### 1.2. Схема взаимодействия

```
Пользователь → Telegram (Bot / WebApp) → n8n → Google Sheets / AI Agent → Ответ пользователю
```

## 2. Оценка варианта MVP без отдельного backend

**Вывод: да**, первую версию можно реализовать на n8n + Telegram Bot + Telegram WebApp + Google Sheets без отдельного backend-сервиса.

### Плюсы
Минимальный бюджет; визуальная логика в n8n; нет деплоя API; Sheets удобны админу; уже есть n8n на VDS.

### Минусы
Квоты Sheets; слабые join; нет транзакций; сложность workflow при росте.

### Ограничения
~200–500 активных пользователей; риск коллизий при частых записях.

### Когда PostgreSQL / backend
При >500–1000 пользователей, задержках Sheets, сложных отчётах/транзакциях. Схему таблиц сразу проектировать «как для PostgreSQL».

## 3. Рекомендуемый стек

| Слой | Выбор |
|------|-------|
| Frontend | Telegram WebApp (HTML/CSS/JS + Mini App SDK) |
| Backend | n8n (Docker на VDS) |
| БД MVP | Google Sheets |
| БД later | PostgreSQL |
| Файлы | Telegram file_id |
| AI | API из n8n |
| Безопасность | initData WebApp, whitelist admin ID, credentials n8n |

## 4. Структура данных

Пользователи, Анкеты (+ статусы доступности), Фотографии, Цены, Места, Чаты, Сообщения, Встречи, Отзывы, Платежи, Уведомления, События, Логи.

## 5. n8n Workflow

WF_01 Регистрация · WF_02 Анкета AI · WF_03 Модерация · WF_04 Каталог · WF_05 Чат · WF_06–07 Встречи · WF_08 Отзывы · WF_09 Статусы · WF_10 Платежи · WF_11 Аналитика · WF_12 Админ

## 6. План разработки

**MVP v1.0:** регистрация → анкета → модерация → каталог → чат → встречи → статусы → отзывы → админка → уведомления

**v1.1:** платежи, аналитика, AI-помощник, антиспам

**v2.0:** PostgreSQL, API, веб-админка, очереди

## 7. Риски

Нагрузка n8n · лимиты Telegram · квоты Sheets · file_id · AI-расходы · безопасность · масштаб

## 8. Рекомендации

Оставить: n8n как backend MVP, file_id, анонимный чат, статусы, audit trail.

Упростить: платежи после core; админка сначала только Telegram.

Принять заранее: chat_id = chat_{profile}_{man}; словари статусов; история изменений; секреты в credentials; идемпотентность webhook; backup Sheets.

Запускать MVP на n8n + Telegram + Sheets без отдельного backend. Критичный путь: регистрация → анкета → каталог → чат → встречи → отзывы → админ.
