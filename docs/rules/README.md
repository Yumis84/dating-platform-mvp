# Правила разработки

Здесь описаны основные правила и соглашения для разработки в проекте.

Предлагаемые правила (предварительно):
- Использовать ветки feature/*, fix/*, hotfix/*; основной поток через pull requests.
- Писать понятные сообщения коммитов и описывать PR.
- Минимальная проверка через код-ревью перед слиянием в main.
- Хранить секреты вне репозитория (Secrets, Vault). Не коммитить .env с секретами.
- Поддерживать документацию в docs/.
- Перед внесением архитектурных изменений — обсуждать в Issues/PR.

Эту страницу можно расширять и уточнять в ходе работы.
