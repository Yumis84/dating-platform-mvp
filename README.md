# Dating Platform MVP v1.0

Цель проекта
------------
Создать минимально жизнеспособный продукт (MVP) Dating Platform, обеспечивающий базовое взаимодействие пользователей через Telegram (бот + WebApp), оркестрацию процессов через n8n, хранение данных в PostgreSQL и использование Google Sheets в качестве дополнительного упрощённого хранилища. AI Agent будет использоваться для помощи в рекомендациях и обработке контента.

Архитектура
-----------
Компоненты MVP v1.0:
- Telegram Bot — приём сообщений и взаимодействие с пользователями.
- Telegram WebApp — фронтенд внутри Telegram для расширенного интерфейса.
- n8n — автоматизация и интеграции (обработка медиа, внешние API, синхронизация с Google Sheets).
- PostgreSQL — основная реляционная БД (проектирование схемы и миграции подготовлены, БД пока не разворачивается).
- Google Sheets — лёгкое внешнее хранилище для MVP (импорт/экспорт данных, ручная корректировка).
- AI Agent — помощник для рекомендаций, модерации и генерации описаний.

Назначение папок
----------------
- /docs — документация проекта (архитектура, правила разработки, ТЗ).
  - /architecture — диаграммы и подробности архитектуры.
  - /rules — правила разработки и соглашения (ветки, PR, секреты).
  - /tz — техническое задание (ТЗ) для MVP.
- /n8n — конфигурации n8n и экспортированные workflows (workflows не создаём пока).
  - /workflows — место для JSON-файлов экспорта workflows.
- /database — схема и миграции базы данных.
  - schema.sql — заготовка схемы (не применять автоматически).
  - /migrations — место для SQL-миграций.
- /webapp — код Telegram WebApp (frontend). Пока пустая заготовка.
  - /src — исходники приложения.
- /docker — docker-compose и другие контейнерные конфигурации.
  - docker-compose.yml — шаблон для локальной разработки/демо (не готов к запуску без настройки).
- /backups — инструкции и политика резервного копирования.

Правила разработки
------------------
- Ветки: feature/* для новых фич, fix/* для багфиксов, main для релизов.
- PR: каждый PR с описанием и целью изменений; код-ревью обязательно для слияния.
- Коммиты: осмысленные сообщения, отдельные логические изменения в отдельных коммитах.
- Секреты: не хранить в репозитории; использовать CI/CD secrets или Vault.
- Документация: любые архитектурные или интерфейсные изменения документировать в /docs.
- CI: добавить базовые проверки (линт, тесты) до слияния в main (план на ближайшее время).

Текущий статус
---------------
Подготовка инфраструктуры MVP v1.0: создана базовая структура репозитория и начальная документация. Рабочий код, n8n workflows и развертывание БД пока не созданы — следующий шаг: проработка схемы БД, настройка docker-compose и создание первых рабочих компонентов.

Если нужно — могу далее:
- Добавить шаблонные CI (GitHub Actions) для линта и тестов.
- Спроектировать подробную схему БД и подготовить миграции.
- Подготовить docker-compose с реальными параметрами для локального поднятия окружения.
